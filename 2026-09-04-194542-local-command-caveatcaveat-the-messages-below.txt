❯ # Continue current 3dmppc-polymer design session                              
                                                                                
  Это продолжение уже идущей сессии по `3dmppc-polymer`.                        
                                                                                
  Не проси меня заново объяснять проект, цель или предыдущие решения.           
                                                                                
  Сначала прочитай текущий репозиторий, git diff и релевантную документацию,    
  затем используй контекст ниже как описание того, что мы сейчас проектируем.   
                                                                                
  Не пиши и не изменяй код без моего явного разрешения.                         
                                                                                
  ## Проект                                                                     
                                                                                
  `3dmppc-polymer` - fantasy console.                                           
                                                                                
  Сейчас основной backend программный и по духу близок к PSX-like console.      
                                                                                
  В будущем я хочу иметь возможность добавлять hardware backend, PBR, path      
  tracing и другие современные возможности, но это сейчас НЕ является задачей.  
                                                                                
  Текущая работа касается lifecycle запуска консоли и требований disc к         
  ресурсам.                                                                     
                                                                                
  ## Главная цель                                                               
                                                                                
  Я хочу, чтобы один и тот же disc мог запускаться на разных host machines.     
                                                                                
  Disc объявляет, какие ресурсы ему нужны.                                      
                                                                                
  Console должна определить, способна ли конкретная host machine обеспечить     
  запуск выбранного disc вместе с расходами самой console.                      
                                                                                
  Если ресурсов недостаточно - disc не запускается.                             
                                                                                
  Если ресурсов достаточно - console поднимает необходимые подсистемы и только  
  после этого запускает код disc.                                               
                                                                                
  ## Важная терминология                                                        
                                                                                
  `machine` / `host machine` - реальный компьютер, на котором запущена fantasy  
  console.                                                                      
                                                                                
  `console` - программа/виртуальная машина 3dmppc.                              
                                                                                
  `disc` - игра/программа для fantasy console.                                  
                                                                                
  Если внешний disc не передан, используется внутренний default disc/default    
  configuration.                                                                
                                                                                
  Один и тот же disc не должен переписываться под конкретную host machine.      
                                                                                
  ## Что уже точно является моим требованием                                    
                                                                                
  При запуске программа должна сначала определить, ЧТО именно она собирается    
  запускать.                                                                    
                                                                                
  Есть два случая:                                                              
                                                                                
  1. Передан внешний disc.                                                      
  2. Внешнего disc нет - используется внутренний default disc.                  
                                                                                
  У внешнего disc есть manifest (`disc.toml`) с его параметрами и требованиями. 
                                                                                
  У default disc тоже должны существовать соответствующие default               
  параметры/requirements.                                                       
                                                                                
  До запуска кода disc необходимо знать его требования.                         
                                                                                
  После того как выбран внешний/default disc и получены его параметры, console  
  должна определить:                                                            
                                                                                
  * требования выбранного disc;                                                 
  * расходы, необходимые самой console для запуска этой конфигурации;           
  * способна ли host machine это обеспечить.                                    
                                                                                
  Если host не способен обеспечить запуск - остановиться до запуска кода disc.  
                                                                                
  Если способен - поднять необходимые console subsystems/resources и только     
  после этого запускать disc.                                                   
                                                                                
  Для внешнего native disc код в итоге загружается через `dlopen`.              
                                                                                
  ## Что сейчас происходит неправильно                                          
                                                                                
  В текущем `main()` слишком рано создаётся `conf`, а `rv_pconsole`/её          
  контроллеры сейчас строятся до того, как стали известны требования выбранного 
  disc.                                                                         
                                                                                
  Из-за этого существующий lifecycle не соответствует новой модели запуска.     
                                                                                
  Это и есть то, что мы сейчас постепенно перепроектируем.                      
                                                                                
  ## Что мы НЕ считаем принятым решением                                        
                                                                                
  Предыдущий AI в этой сессии много раз делал архитектурные выводы без          
  достаточного основания.                                                       
                                                                                
  Следующие вещи НЕ считать принятыми только потому, что они могли попасть в    
  предыдущую документацию или незакоммиченный код:                              
                                                                                
  * `request / capability / grant` как обязательная архитектурная модель;       
  * отдельный `cost model`;                                                     
  * routing tables между console memory и host memory;                          
  * обязательное резервирование всего worst-case объёма на старте;              
  * запрет runtime realloc;                                                     
  * обязательный auto-downgrade или обязательный запрет auto-downgrade;         
  * bit-exact hardware backend;                                                 
  * обязательное разделение `rv_pcloader::load()` на две публичные стадии;      
  * обязательное существование `rv_compatibility_check_launch_console`;         
  * обязательное существование ровно двух compatibility checks.                 
                                                                                
  Это могут быть варианты, но они требуют отдельного обоснования и моего        
  решения.                                                                      
                                                                                
  Не защищай их и не пытайся сохранить им ответственность.                      
                                                                                
  ## Что произошло непосредственно перед переносом сессии                       
                                                                                
  Мы начали рассматривать новый lifecycle сверху вниз, начиная с:               
                                                                                
  `int main(int argc, char** argv)`.                                            
                                                                                
  Я заметил, что `main()` сейчас сразу создаёт `conf`, хотя ещё не известно,    
  какой disc/default configuration будет запускаться.                           
                                                                                
  Мы начали обсуждать две предполагаемые проверки:                              
                                                                                
  * `rv_compatibility_check_launch_console`                                     
  * `rv_compatibility_check_launch_disc`                                        
                                                                                
  Первая предполагалась как проверка вида:                                      
                                                                                
  "эта host machine вообще способна поднять console"                            
                                                                                
  Вторая:                                                                       
                                                                                
  "выбранному disc нужно N, host machine может дать M"                          
                                                                                
  Но в процессе выяснилось, что смысл первой проверки пока НЕ установлен.       
                                                                                
  Предыдущий AI несколько раз противоречил себе:                                
                                                                                
  * сначала говорил, что ранняя проверка обязательна;

  * затем снова попытался сохранить раннюю проверку, назначив ей display/audio. 
                                                                                
  Поэтому сейчас существование и ответственность                                
  `rv_compatibility_check_launch_console` НЕ определены.                        
                                                                                
  ## Текущий mental model запуска                                               
                                                                                
  Пока можно считать подтверждённой только такую общую последовательность:      
                                                                                
  ```text                                                                       
  process starts                                                                
  -> parse input arguments                                                      
  -> determine external disc or default disc                                    
  -> obtain selected disc/default parameters and requirements                   
  -> now we know what configuration needs to run                                
  -> determine whether host machine can support that configuration              
  -> if not: fail before disc code starts                                       
  -> if yes: construct/start required console subsystems/resources              
  -> load/start disc code                                                       
  -> run                                                                        
  ```                                                                           
                                                                                
  Не делай эту схему более конкретной без исследования.
