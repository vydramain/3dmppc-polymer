# 0004. Шрифты

Статус: принято.

## Контекст

В pdklib есть растровый шрифт дисков `pdk/lib/include/pdklib/rv_font/rv_font_data.hpp`: чернила 5x7 в
клетке 8x8, 8 байт на глиф, ASCII 32..126 и заглушка notdef. Консоль его не рисует сама: диск
загружает атлас как обычную текстуру (`rv_font.hpp`), а пауза консоли растеризует те же биты прямо в
ARGB-буфер (`src/rv_pconsole/rv_pcpause_overlay.cpp`). Атлас ASCII - 16x6 клеток, 128x48 IDX4,
3072 байта (`rv_font_texture.hpp`).

UI-06 задаёт ориентир IBM VGA для моноширинного текста и требует кириллицы.

## Решение

Редактор:

- Шрифт интерфейса - растровый 5x7 в клетке 8x8 из pdklib (`rv_font_data.hpp` и блок кириллицы
  `rv_font_cyrillic.hpp`), размер 8 * N. Решение владельца 2026-09-25: интерфейс рисуется без
  масштаба сверх `--scale`. Публичного API для растровых глифов у ImGui нет, поэтому редактор
  собирает из битов `rv_font` TrueType-файл в памяти - каждый пиксель квадратный контур на целой
  сетке - и загружает его штатным `AddFontFromMemoryTTF` (`editor/src/font/rv_editor_font_ttf.cpp`).
- Шрифт кода (nvim, 0005), Output и терминала - растровый 6x11 редактора (решение владельца
  2026-09-25: 9x16 слишком крупный): чернила 5x10, заглавные в строках 1-7, строчные 3-7, выносные
  8-9, строка 0 - знаки над Ё и Й. Таблица `editor/src/font/rv_editor_font_code_data.hpp` нарисована
  для редактора; тем же способом, что `rv_font`, превращается в TrueType в памяти, размер 11 * N.
- Контуры обоих шрифтов лежат на целой сетке, поэтому при размере, кратном клетке, края совпадают с
  границами пикселей и сглаживания нет. Сэмплирование - nearest (0001).
- Масштаба по умолчанию нет. Масштаб - целое N из `--scale N`, по умолчанию 1. Окно создаётся с
  `SDL_WINDOW_HIGH_PIXEL_DENSITY`, ImGui получает размер окна в пикселях при framebuffer scale 1, а
  координаты мыши переводятся в пиксели рендера: плотность дисплея ничего не увеличивает сама.

Диски:

- Кириллица добавляется в `rv_font` блоком. ASCII и notdef есть всегда; диск добавляет блоки маской
  (`rv_font_block_cyrillic`) при сборке атласа и указывает ту же маску в `rv_font_style`.
- Блок кириллицы - 66 глифов (U+0410..U+044F, U+0401, U+0451) в той же сетке 5x7 в 8x8, перерисованных
  по PxPlus IBM VGA 9x16. Таблица - адаптация шрифта и распространяется под CC BY-SA 4.0
  (`rv_font_cyrillic.hpp`).
- Атлас с кириллицей - 128x88, 5632 байта. Диск без блоков остаётся с прежним атласом в 3072 байта,
  байт в байт.
- Разметка текста идёт по символам UTF-8. Байт, с которого не начинается корректная
  последовательность, рисуется notdef, по клетке на байт, как раньше.

## Последствия

- Интерфейс редактора и диски рисуют одним шрифтом `rv_font`; редактор берёт его биты из pdklib,
  атлас дисков ему не нужен.
- UI-06: два шрифта, две таблицы.
- Масштаб только целый: NFR-03 проверяет 100% и 200%.
- При `--scale 1` буквы интерфейса высотой 7 пикселей.
- Диск, подключивший блок кириллицы, несёт таблицу под CC BY-SA 4.0 и указывает атрибуцию из
  `third_party/pxplus-ibm-vga/ORIGIN.md`. Консоль и диски только с ASCII таблицу не содержат.
  Редактор несёт её в шрифте интерфейса и указывает ту же атрибуцию в README.
