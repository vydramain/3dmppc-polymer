# 0005. Редактор кода: один процесс nvim --embed на окно редактора

Статус: принято.

## Контекст

Многострочный ввод ImGui не годится для редактора кода. nvim, запущенный внутри терминала, виден
редактору только как поток символов: неизвестно, какие буферы не сохранены (AC-22), а переход из
Problems к файлу возможен только имитацией нажатий.

`nvim --embed` отдаёт stdin/stdout под msgpack-rpc; так работают GUI-клиенты вроде Neovide.
Проверено на NVIM v0.11.6: `nvim_ui_attach` с `ext_multigrid` отдаёт общую сетку 1 и по сетке на
окно, `vsplit` добавляет новую сетку, `nvim_ui_try_resize_grid` меняет размер одной сетки.

## Решение

Тайл кода - окно одного общего UI-клиента nvim.

- Один процесс `nvim --embed -u <конфиг редактора>` на окно редактора. Он запускается с первым
  тайлом кода и завершается при закрытии проекта или редактора, после вопроса о несохранённых
  буферах. Тайлы кода своих процессов не создают (LAY-08, 0002). `-u` не загружает личный
  `init.lua` и плагины; подключение своего конфига - отдельная опция позже.
- Подключение: `nvim_ui_attach(cols, rows, {rgb = true, ext_linegrid = true, ext_multigrid = true})`.
  Каждый тайл кода - одно окно nvim со своей сеткой. Сетка 1 общая: в ней командная строка и
  сообщения, редактор рисует её полосой под тайлом с фокусом.
- Обрабатываются события: `grid_resize`, `grid_line`, `grid_clear`, `grid_scroll`,
  `grid_cursor_goto`, `grid_destroy`, `win_pos`, `win_hide`, `win_close`, `msg_set_pos`,
  `hl_attr_define`, `default_colors_set`, `mode_change`, `flush`. Остальные пропускаются. Курсор
  пока всегда блочный (`mode_info_set` позже).
- Тайл и окно: новый тайл кода открывает окно `nvim_open_win(buf, true, {split = ...})`; размер
  тайла в ячейках уходит в `nvim_ui_try_resize_grid`. Собственную раскладку окон nvim редактор не
  показывает: сетка окна кладётся в его тайл.
- Запросы редактора: `nvim_set_current_win` при смене фокуса, `nvim_input` (клавиши),
  `nvim_command` (`edit +N file` для перехода из Problems), `nvim_exec_lua` (несохранённые буферы
  через `getbufinfo({bufmodified = 1})`), `nvim_win_close`.
- Закрытие тайла кода: если буфер его окна изменён и не показан ни в одном другом окне, редактор
  спрашивает Save / Discard / Cancel. Save - `:write`, Discard - `:bdelete!`, Cancel оставляет тайл.
  Затем окно закрывается. Закрытие проекта или редактора задаёт тот же вопрос по всем изменённым
  буферам (AC-22).
- msgpack - свой небольшой кодек без внешней зависимости: кодируем массивы, строки, целые и map
  опций; разбираем nil, bool, целые, float, str, bin, массивы, map и ext.
- Чтение pipe - в отдельном потоке в ограниченную очередь; UI-поток применяет события на кадре
  (DEV-05).
- Отрисовка сеток - `ImDrawList` шрифтом кода (0004). Клавиши ImGui переводятся в нотацию
  `nvim_input` (`<C-s>`, `<S-Left>`).
- Конфиг "обычного редактора" - один Lua-файл без плагинов: старт в режиме вставки,
  Ctrl+S/C/V/X/Z, выделение Shift+стрелками, одна клавиша переключает в обычный vim-режим.
  Подсветка - встроенный treesitter и свой colorscheme с палитрой Mocha.
- Объём: четыре файла, каждый меньше 512 строк - кодек, процесс и RPC-канал, модель сеток,
  отрисовка и ввод.

Сознательно нет: собственных виджетов для cmdline и popupmenu, плавной прокрутки и анимаций,
нескольких процессов nvim. Каждое добавляется позже своей `ext_*` опцией.

## Последствия

- Раздел 10 требований (TXT-01..TXT-07) описывает редактор кода как клиент nvim; ARC-05 называет
  nvim обязательной зависимостью текстового редактора.
- Без nvim Text Editor показывает причину, остальные панели работают.
- Сбой процесса nvim затрагивает все тайлы кода сразу - цена одного процесса. Swap-файлы nvim не
  отключаются, несохранённый буфер восстанавливается штатным `:recover`.
- Терминал (TRM-01) - отдельный тайл с PTY; его устройство здесь не решается.
