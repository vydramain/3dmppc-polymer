# 0005. Редактор кода: минимальный клиент nvim --embed

Статус: принято.

## Контекст

Многострочный ввод ImGui не годится для редактора кода. nvim, запущенный внутри терминала, виден
редактору только как поток символов: неизвестно, какие буферы не сохранены (AC-22), а переход из
Problems к файлу возможен только имитацией нажатий.

`nvim --embed` отдаёт stdin/stdout под msgpack-rpc; так работают GUI-клиенты вроде Neovide.
Проверено на NVIM v0.11.6 через `api_info()`: 10 UI-опций, 72 UI-события, особые типы RPC -
`Buffer`, `Window`, `Tabpage`.

## Решение

Тайл кода - лёгкий UI-клиент nvim.

- Один процесс `nvim --embed -u <конфиг редактора>` на тайл кода. `-u` не загружает личный
  `init.lua` и плагины; подключение своего конфига - отдельная опция позже.
- Подключение: `nvim_ui_attach(cols, rows, {rgb = true, ext_linegrid = true})`, все прочие `ext_*`
  выключены. nvim сам рисует командную строку, меню автодополнения и сообщения внутри одной сетки.
- Обрабатываются 9 событий: `grid_resize`, `grid_line`, `grid_clear`, `grid_scroll`,
  `grid_cursor_goto`, `hl_attr_define`, `default_colors_set`, `mode_change`, `flush`. Остальные
  пропускаются. Курсор пока всегда блочный (`mode_info_set` позже).
- Запросы редактора: `nvim_input` (клавиши), `nvim_ui_try_resize` (размер тайла в ячейках),
  `nvim_command` (`edit +N file` для перехода из Problems), `nvim_exec_lua` (несохранённые буферы
  через `getbufinfo({bufmodified = 1})` перед закрытием).
- msgpack - свой небольшой кодек без внешней зависимости: кодируем массивы, строки, целые и map
  опций; разбираем nil, bool, целые, float, str, bin, массивы, map и ext.
- Чтение pipe - в отдельном потоке в ограниченную очередь; UI-поток применяет события на кадре
  (DEV-05).
- Отрисовка сетки - `ImDrawList` шрифтом редактора (0004). Клавиши ImGui переводятся в нотацию
  `nvim_input` (`<C-s>`, `<S-Left>`).
- Конфиг "обычного редактора" - один Lua-файл без плагинов: старт в режиме вставки,
  Ctrl+S/C/V/X/Z, выделение Shift+стрелками, одна клавиша переключает в обычный vim-режим.
  Подсветка - встроенный treesitter и свой colorscheme с палитрой Mocha.
- Объём: четыре файла, каждый меньше 512 строк - кодек, процесс и RPC-канал, модель сетки,
  отрисовка и ввод.

Сознательно нет: `ext_multigrid`, собственных виджетов для cmdline и popupmenu, плавной прокрутки и
анимаций, нескольких UI на одном процессе. Каждое добавляется позже своей `ext_*` опцией.

## Последствия

- Раздел 10 требований (TXT-01..TXT-05) описывает встроенный редактор и должен быть переписан под
  nvim.
- nvim становится внешней зависимостью времени работы. ARC-05 требует, чтобы без tools файлы
  открывались и редактировались; без nvim редактировать нечем. Противоречие снимается в требованиях.
- Терминал (TRM-01) - отдельный тайл с PTY; его устройство здесь не решается.
- Живое рукопожатие с `--embed` ещё не проверялось; оно проверяется при реализации RPC-канала.
