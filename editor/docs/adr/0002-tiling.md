# 0002. Тайловое рабочее пространство: своё дерево раскладки

Статус: принято. Закрывает LAY-01..LAY-09 на уровне архитектуры.

## Контекст

Ветка `docking` Dear ImGui даёт готовый DockSpace, но в `v1.92.9b-docking` размеры узлов
сохраняются в `imgui.ini` в пикселях (`SizeRef=%d,%d`, `Size=%d,%d`), временного разворачивания
тайла нет, а вкладки и заголовки рисует сама ImGui. LAY-02 требует отношений, LAY-01 -
разворачивания, UI-02 - скошенных вкладок и stippled-заголовков.

## Решение

Своё дерево раскладки поверх ImGui `master`.

```cpp
struct rv_editor_tile_split { rv_editor_axis axis; float ratio; uint32_t first, second; };
struct rv_editor_tile_leaf  { std::vector<rv_editor_pane_id> tabs; uint32_t active; };
// узел - split или leaf; у раскладки ещё maximized_leaf
```

- Раскладка - только представление. Панель - вид на модель (runtime session, build job, документы),
  модель живёт вне UI. Закрытие тайла не останавливает runtime и не отменяет сборку (LAY-09);
  несколько Output или code-панелей не создают процессов (LAY-08).
- Панели хранятся в отдельном реестре `rv_editor_pane_id -> вид панели`. Состояние панели (окно
  nvim, фильтр Output) хранит её модель по тому же id; реестр и дерево о нём не знают.
- Закрытие тайла, чья панель держит несохранённое (тайл кода, 0005), идёт через запрос: панель
  отвечает, можно ли закрыть сейчас, и может отменить закрытие. Остальные панели закрываются сразу.
- Операции над деревом - чистые функции без ImGui: split, merge-to-tabs, move, close, maximize,
  clamp по минимальным размерам.
- Размеры хранятся долями (`ratio`), не пикселями (LAY-02).
- Минимальный размер задаёт сама панель, дерево его только применяет:

  ```cpp
  struct rv_editor_size { int32_t w, h; };
  // у каждой панели: rv_editor_size min_size() const;
  ```

  Game: размер кадра, который сообщает консоль, умноженный на целый масштаб (>= 1), плюс рамка
  тайла. До первого кадра - только рамка и явная пометка "размер неизвестен" (LAY-03). Остальные
  панели - по своим текстам и контролам (LAY-04). Ограничение пересчитывается при каждом изменении
  минимума, а не только при изменении окна. Окно меньше минимума дерева прокручивается: тайлы не
  сжимаются ниже своих минимумов, и все контролы достижимы; M разворачивает один тайл на всё окно.
- Fit - отдельный, явно обозначенный режим Game; на минимум он не влияет (LAY-05).
- Отрисовка: тайл - окно из виджетов каталога (0003): рельефная рамка, заголовок с кнопками X
  (убрать тайл со всеми его панелями) и M (развернуть и вернуть), утопленная область содержимого и
  под ней скошенные вкладки, когда панелей несколько. Разделитель - `rv_editor_splitter`. Тайлы не
  перетаскиваются мышью; разворачивание - только кнопкой M, двойной щелчок ничего не делает.
  Файл раскладки хранит только панели, которые показывает дерево, перенумерованные по порядку.
- Рабочих пространств три: Default, Test и Release. У каждого своё дерево, реестр панелей один на
  окно; переключение меняет только показываемое дерево. Панель, которая есть в дереве хоть одного
  пространства, сохраняет своё окно nvim и свой shell; переключение не трогает процессы, сборку,
  буферы и журнал.
- Сохранение - свой текстовый файл на пространство: `$XDG_CONFIG_HOME/3dmppc-editor/layout` у
  Default (тот же файл, что писали прежние версии), `layout-test` и `layout-release` (без
  переменной - `~/.config/3dmppc-editor/...`); пространство, показанное последним, - в файле вида.
  Первая строка `3dmppc-editor-layout 1`, дальше по записи на панель и на узел дерева. Файл
  читается, только если он целиком корректен; иначе, как и без файла, пространство берёт свою
  стартовую раскладку без потери документов (LAY-06). Запись при выходе - во временный файл и
  rename поверх.
- Стартовые раскладки состоят только из написанных панелей. Default: Files слева, Code над Output
  и Terminal (две вкладки) в центре, Game над Runtime Controls справа. Test (референс `0008`):
  полоса Runtime Controls высотой по содержимому над Game (62%) рядом с Observe, Code и Files,
  снизу Runtime Log, Findings и Terminal (верх 72%). Release (референс `0007`): полоса Release
  Controls над Release Candidate (35%) рядом с Game (65%), снизу Build Log и Playtest Log. Layout
  > Reset сбрасывает только показанное пространство; Code и Scene из референсов `0003` и `0005`
  лежат в подменю Layout > Reference Layouts и ставятся в показанное пространство. Сохранённая
  раскладка читается как есть и сама не заменяется.
- Полоса управления получает минимум высоты по тому, что нарисовала в прошлом кадре; отношение её
  разделителя 0, поэтому она ровно такой высоты, пока пользователь её не растянет.
- Тайл с фокусом обведён латунью (`selection`) вместо чёрного.
- Разделение, закрытие тайла или панели и смена вида панели записываются во время отрисовки и
  применяются после неё, одно изменение за кадр: отрисовка не держит ссылок на изменяемое дерево.

## Последствия

- Перемещения тайла нет: LAY-01 в части «переместить» не закрыт.
- Модель дерева не включает заголовки ImGui; это проверяется по include.
- Именованных пользовательских раскладок нет: есть три пространства со своими сохранёнными
  раскладками. LAY-06 в части произвольных имён не закрыт.
